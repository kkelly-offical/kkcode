## 串行和停止条件

`serial-batch.mjs`只在一个完整案例返回后派发下一个；`host-runner.mjs`调用已冻结的
受限VM适配器，检查安装包、清单、预算、后端空闲及清理回执。
独立进程锁防止重复启动；模型代理另外保证请求串行，子任务也共享同一预算。

普通交付失败保留失败后可继续下一项。以下情况停止整批，并把剩余项目标为未运行：

- 新模型用量未知、仍有未结算请求或模型传输/协议异常；
- 工具操作仍为pending/uncertain或原生验收报告未知效果；
- 清理、身份、部署哈希、隔离环境或评分器结果无法核验；
- 剩余预算/时间不足以容纳下一项；收到停止标记。

不代替用户确认未知工具操作，不清空失败或未知账本，不扩大权限来换取通过。
固定截止看门狗独立于批次控制器，结束时撤销本批入口并停止本批服务，保留现有模型服务。

## 明天查看

冻结执行目录：`/root/kkcode-106-stable-harness-20261002`。

```sh
node evaluation/overnight/status.mjs /root/kkcode-106-stable-harness-20261002
systemctl status kkcode-106s16-overnight.service --no-pager
```

- `private/REPORT.md`：逐项汇总。
- `private/status.json`：当前项目、停止原因、已完成与未运行项目。
- `runs/<id>/agent.jsonl`：原始运行事件；同目录保留退出、工具效果、评分与清理回执。
- `private/requests.jsonl`：不可清零的请求账本。
- `private/closure-receipt.json`：最终用量、旧账继承、服务关闭与排空证据。
- `manifest.json`：固定包、环境、脚本与提示的哈希。

这些目录包含私有执行记录，不能整体发布到Git或Release。
人工需要提前停止时，在受授权宿主执行：

```sh
node /root/kkcode-106-stable-harness-20261002/close-night.mjs --stop
```

停止会保留已发生的副作用与可能的未知用量，不能直接重新启动同一批次。
