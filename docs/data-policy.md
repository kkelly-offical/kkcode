# 项目数据出域策略

[文档导航](README.md) · 适用源码：1.1.6；[发行状态](versions.md)

`data_policy` 限制 KK Code 受管理的模型请求和内置网页工具的目标。默认不配置时保留原行为；它只收紧范围，不授予工作区信任、工具权限或凭据，也不代替执行沙箱。

```yaml
data_policy:
  providers: [local-vllm, enterprise]
  model_origins: ["http://127.0.0.1:8000", "https://models.example.com"]
  web_origins: ["https://docs.example.com", "https://mcp.exa.ai"]
```

- `providers` 匹配 provider 配置名，不是底层协议名或模型 ID。
- `model_origins`、`web_origins` 匹配完整 origin（协议、主机和端口），不接受路径、查询、用户名密码、通配符或相对 URL。尾部 `/` 可以省略。
- 某字段缺省表示该维度不额外限制；`[]` 表示该维度全部拒绝。`{}` 不取消继承的限制。
- 用户配置、项目配置、`.env` 与宿主管理员策略取交集。项目或环境覆盖不能把上层拒绝的目标重新放行。
- 未知字段、拼错类型、`null`、非法 origin 会显示错误并拒绝受管理的出站请求，不会警告后忽略。修正配置并重新加载后才恢复。
- `.env` 支持 JSON 数组，例如 `KKCODE_DATA_POLICY__PROVIDERS=["local-vllm"]`。这与一般环境字段的首文件优先不同；所有相关 `.env` 的策略都取交集，项目 `.env` 不能遮蔽用户 `.env` 的限制。

## 覆盖范围

模型路由的流式、非流式、远程 token 计数与模型列表发现均先校验；标题、压缩、审查等辅助调用通过相同路由，不能选择越界供应商。后台子代理会继承父任务的有效限制，与子工作目录配置再次取交集。模型端点覆盖及协议专用端点也检查实际 origin。内置推理适配器拒绝自动重定向，防止通过 307/308 将提示内容送到另一目标。

`webfetch` 与 `http_request` 每一跳校验 `web_origins`；Browser 每个 HTTP 子资源、导航和允许的开发 WebSocket 都校验目标；内置 `websearch`、`codesearch` 向 Exa 发请求前也校验。因此只允许文档站点但不允许 Exa 时，外部搜索会明确拒绝。

私有模型端点不是一概禁止：允许的本地 vLLM 可以使用。此前已经存在的模型路由传输检查（推理、远程计数、模型发现）仍拒绝在明文 HTTP 上发送凭据；这不是本次新加的所有工具通用禁令。本地无认证服务请明确配置空 `api_key_env` 和空密钥，经过该路由的带密钥部署使用 HTTPS。网页工具的私网开关和 metadata 禁令仍然生效。

策略错误只报告字段及拒绝原因，不输出 API Key、URL 密码、查询令牌或完整请求内容。模型切换不会继承前一个模型的授权；每次调用重新检查目标。

## 宿主管理员策略

内部配置加载器支持 `loadConfig(cwd, { adminDataPolicy })`，结果可以作为内核的 `configState`；本阶段没有增加独立的公共 SDK 配置加载入口。该参数不是项目文件可以设置的管理员权限；它只增加一个不可由较低层放宽的交集。宿主必须保护管理员输入和配置进程。当前未加入系统级策略文件发现、企业网关策略下发或远程修改管理员策略的功能。

## 安全边界与未覆盖范围

这不是完整 DLP 或操作系统防火墙。任意 Shell、宿主插件、自定义 provider 的内部网络、第三方 MCP 服务以及其下游行为不能单靠 URL allowlist 隔离，必须配合受限执行器和组织网络策略；当前文档不将这些路径标为已封闭。已允许的 origin 若反向代理到其他服务，其实际数据处理方式由部署方负责审核。

严格项目应同时禁用或隔离不受信任的可执行扩展与 Shell 出网。在严格执行后端全部验收完成前，不应仅凭本配置宣称“所有数据绝不出域”。
