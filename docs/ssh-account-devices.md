# Android SSH、账号设备与任务生命周期

[文档导航](README.md) · 适用源码：1.1.6；[版本与验收状态](versions.md)。Android仍为SSH直连，Web不提供SSH代理。

## 哪一端做什么

| 组件 | 职责 |
| --- | --- |
| Android | 原生 SSHJ 直连、主机指纹确认、本地凭据加密、端口转发和会话 UI |
| 企业网关 | 账号/组织隔离的 SSH 地址簿；不连接 SSH、不保管 SSH 密码/私钥 |
| Web | 继续管理中继设备和会话；不新增 SSH 客户端 |
| 工作电脑 CLI | 启动内核与受控 Device API，持有工作区、模型配置、历史及任务 |

网关登录和 SSH 登录不是同一凭据。账号记忆只帮助找到机器，不替代 SSH 认证。
未登录也可本机保存 SSH 连接；未登录资料不会静默迁移到另一个组织账号。

## 使用

在连接菜单的 SSH 分组添加机器，填写主机、SSH 端口、用户名及本机凭据。
先核对设备提供的 SHA256 指纹，再确认连接；主机身份变化不能自动忽略。
本机记住的凭据绑定主机、端口、用户名和已确认指纹；账号资料变更后需要重新核对，
不会把旧密码自动用于变更后的目标。成功连接还会固定本机指纹，不由云端更新静默替换。
默认只授权 home；“所有普通目录”需要在连接设置里显式选择。
工作区信任、工具审批与远端 OS 用户权限依旧有效，目录授权不等于提升权限。

设备条将 SSH 和网关机器并列；连接菜单可断开当前连接、编辑/移除资料。
上方“添加网关连接”只处理网关；SSH 在下方独立分组添加。点击当前已连接的
SSH 不会重复登录或打开弹窗。自动恢复缺少凭据时保留列表并提示，不抢占页面；
主动选择该 SSH 才打开凭据表单。主机身份变化仍需重新核对指纹。
断开只关闭客户端连接，不等于取消远端任务。要取消任务，使用对话中的停止按钮。
移除连接会清除该手机保存的对应 SSH 密码/私钥，不删除远端项目或会话。

## 生命周期

1. App 用 SSH 执行 `kkcode ssh-host --json --home-only --port 18271`。
2. 启动器与 SSH session 分离，宿主只监听目标机 `127.0.0.1`。
3. 本地私密控制 socket 签发 60 秒一次性配对票据；票据不写账号库。
4. 手机建立 SSH 本地转发并配对，20 秒发送一次受认证心跳。
5. 关闭 App / 杀掉手机进程 / 网络断开后，目标机在途工作继续。
6. App 重新打开，使用本机保存的凭据重连，可恢复最后一个 SSH 会话和实时状态。
   仅退到后台而进程未销毁时，回前台也会探活；隧道/配对过期可自动重建，失败最多
   重试 5 次。没有本机凭据或主机身份变化时要求用户处理，不自动放宽指纹验证。
7. 任务与排队工作均结束，且 75 秒无客户端活动后，宿主退出；下次重新启动仍读
   同一本地历史，而不是另起一套丢失上下文的存储。

若目标机已有兼容的前台 `kkcode remote`，可以复用它的 Device API，但目录范围与
本地 Web 端口必须匹配。此时是 `foreground-remote`，关闭该 Remote 终端仍会停止
暴露；App 不会把用户明确启动的前台服务偷偷变成永久后台服务。

机器关机、OS 杀死 Node、模型调用故障不等同于手机断线，不承诺任务跨这些故障
自动继续。等待人工审批的任务仍有审批超时；不会因为手机离线自动批准危险操作。
旧 CLI 不支持 ssh-host 时明确要求升级，不回退到“关 App 就杀任务”的旧启动方式。

## 地址簿 API

- `GET /api/v1/connections/ssh` → `{revision, items}`。
- `POST /api/v1/connections/ssh` → `{revision, connection}`。
- `POST /api/v1/connections/ssh/:id/delete` → `{revision}`。

认证与网关其他账号 API 相同。所有修改要求当前 revision，冲突返回 409；
每账号最多 100 项。连接字段只允许 `id/name/host/port/username/remotePort/hostKey/folders`，
发送 password/privateKey/未知字段会被拒绝。主机、端口或用户变化时清除服务器端指纹，
客户端必须重新验证。地址簿没有 SSH 私钥导出接口。

网关不可达/版本过旧时本机缓存仍可直连；未同步项保留等待后续同步。
网关备份包含这些非凭据连接资料；企业应将主机/用户名也作为组织内部信息保护。

## 常见问题

- “无法读取 local-vllm”：模型配置属于当前被控电脑。切换设备后重新选择它自己的渠道；
  不会沿用另一台机器的渠道名。模型请求在目标电脑执行，SSH 不会代转其他机器的 vLLM。
- 连接成功后 API 失联：App 会重建隧道/配对，不自动重放可能已有副作用的业务请求。
  长期离线、没有本机凭据、指纹变化仍需用户处理。
- 新对话失败留下空记录：新版创建前校验模型和模式，首页隐藏明确无内容的草稿；
  不删除历史。旧设备未提供标记时不根据标题猜测，需升级目标机 CLI 获得完整修复。
- 错误优先显示中文原因与下一步操作，兼容旧主机的平铺 message/code；
  安全限制、目录授权、项目配置信任不会因本次文案优化而关闭。
