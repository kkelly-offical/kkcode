## 产品方向

普通用户选择渠道和模型后，尽量自动获得正确的参数。模型决定如何完成工作；宿主管理实际资源、权限、执行状态与恢复。Agent / Auto / YOLO 继续保持相同能力和单一模式入口；Ultra 保留持久任务能力，减少固定工程流程。

模型能力、用户偏好和任务授权分别处理：API 声明能支持什么，不等于用户要求每轮用满额度，也不能授予新增权限或扩大已冻结的预算。字段缺失时优先分析已有返回数据及协议语义，再使用适用规格与默认兜底；不能推断的保持未知，不把估算冒充官方参数。采样参数允许不发送，以采用服务端默认值。

## 参数兜底与思考交互约定

用户进一步明确：以自动配置和可靠兜底为主，最大输出等技术参数一般不需要人工操作；用户主要调节思考强度。沿用原清单范围，收敛为以下默认行为：

1. 接口有明确有效值，直接采用；缺少字段则分析已有元数据中的模型版本、协议、支持参数、默认值及限额之间的关系。适用的已知规格和合理默认用于补足空缺，来源标注为推断／兜底。不会为了补齐表单而额外发起模型推理，也不根据一轮实际输出或模型自述猜测硬上限。
2. 默认使用模型／服务端推荐的思考设置；没有推荐值时使用与能力匹配的产品兜底，不统一强制最高档。输出额度、思考预算和正文空间由系统协调。
3. 有明确思考分级：按支持的实际顺序建立数字等级 `1…N`，映射回接口的合法枚举或数值。界面显示中文档名和简短说明，数字只表达该模型内的顺序，不声称跨模型等价，也不把内部等级直接发送给只接受字符串枚举的接口。
4. 只有思考／非思考：仅显示“思考”开关。若明确只支持始终思考，显示状态，不提供无效关闭；能力不明时采用默认，不伪造分级或开关。
5. 只提供连续思考预算、且确认可调：按当前模型有效范围及本次输出预算动态换算少量数字预设档位，不按档名写死通用的绝对 token 阈值；仍遵守协议硬下限并为正文留空间。档位是产品预设，不能标为官方分级；缺少可确定的范围时使用默认，不臆造数值，原始数值不要求普通用户填写。

按用户要求预备五档，增加 `xhigh`，位于 `high` 与 `max` 之间。以下为已确认对应语义时的显示映射；接口返回不同档位集合时按真实能力裁剪或扩展，名称与说明可相应调整，保留原生值供详情核对，不强行凑足五档。名称采用简洁古汉语风格，附白话说明：

| 五档完整时的等级 | 原生值示例 | 显示名称 | 简短说明 |
| --- | --- | --- | --- |
| 1 | `low` | 略思 | 较轻思考 |
| 2 | `medium` | 审思 | 仔细推敲 |
| 3 | `high` | 深思 | 深入推演 |
| 4 | `xhigh` | 精思 | 更缜密推演 |
| 5 | `max` | 穷理 | 更充分推究 |

“自动”是使用默认设置的选择，不占思考等级；可关闭时的非思考状态可标为“直答”，与强度等级分开。切换模型后重新解析可用选项；子代理继承思考偏好时映射到自身能力，不直接照搬父模型等级或预算。CLI、Web 和 Android 采用相同映射，关闭必须在真实请求中生效，不能将省略参数一概等同于关闭。

档名是显示层，实际配置保留模型原生值与来源，实现界面选择→原生参数，以及已生效配置→界面选中项的双向映射。用户要求预备五档，并随接口返回灵活调整用户看到的选项和表述，不固定思考阈值；具体规则为：

- 若接口明确提供 `low / medium / high / xhigh / max` 五档，可分别显示略思／审思／深思／精思／穷理，发送时仍使用该协议要求的原生枚举和参数结构。此例不表示所有模型都支持这些值。
- 若只支持三档，则呈现三档；支持 `low / medium / high / max` 时隐藏精思，支持 `low / medium / high / xhigh` 时隐藏穷理。不能因 `xhigh` 恰为当前最高档就改发 `max`。多于五档则保留真实独立档位，不把额外等级吞掉。不能用不同标签重复发送同一个原生值来凑档数，也不能只根据枚举列表位置猜测未声明的强弱关系。
- API 提供等级、推荐值或范围时直接解析；未提供时结合已有模型版本、协议和适用规格确定映射，仍无法确定则用默认。不根据模型名称独自断言一定支持 `max`，也不额外推理探测。
- 已保存的原生参数无法被当前目录确认时显示其实际值及待确认状态，不误标为一个已支持档位。模型／端点／能力版本改变后重新解析，不能把旧 token 数当成另一个模型的同档强度。
- 检查枚举顺序变化、缺少 `xhigh` 或 `max`、三／四／五／更多档位、只支持开关、连续预算边界、未知能力，以及用户选项到真实请求再回到界面的一致性。数字等级仅代表同一模型内的相对强度，不表示不同模型推理量或效果相等。

## 自动配置的边界

- 能自动读取：接口明确提供的限额、支持参数、能力、服务端默认值和相关元数据；实际使用还要受当前协议适配器及部署限制约束。
- 应由产品与任务决定：是否委派、并发数、工作步数、上下文交接粒度、哪些检查有意义。API 无法提供这些任务策略，不能伪装成自动发现的模型参数。
- 保留人工覆盖，但明确额度不能突破实际端点能力；显式偏好与自动发现分开存储，刷新能力不会覆写用户意图。
- 不自动扩大宿主冻结的预算、数据范围、账号、项目或任务权限。原生压缩和跨渠道路由不能只凭目录中一个支持标记就启用。
- 新实现先使用脱敏目录响应和模拟服务核对参数及生命周期；不另建评测框架，不重启旧批次。新的真实推理仍需要有效授权和预算。
