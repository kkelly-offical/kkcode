# 第三预览版安全告警复核

本页记录发布前实际复核，不是零漏洞证明。CodeQL 任务成功只表示扫描完成；
依赖审计、功能测试和静态告警处置是不同的门禁。

## 本轮确认并修复的边界

- Web 曾把网关返回的 `verification_uri_complete` 直接交给 `window.open` 和
  `href`（旧主分支告警 #49–52）。现在 CLI/Web/Android 都只从严格的 8 位
  登录码构造网关固定 `/login?code=...` 路径，不导航任意响应 URL。Web 始终
  同源，CLI/Android 使用明确选择并校验过的规范网关 origin。外部企业 SSO
  的跳转仍由网关服务端验证过的 OIDC 流程完成。
- CLI 的登录轮询、刷新、撤销、登出和 SDK 请求禁止自动重定向；Android HTTP
  与 SSE 同样关闭重定向，WSS 明确不跟随重定向。307/308 不得把 JSON 中的
  refresh/device code 或 RPC 内容带到另一个端点。代理应透明转发 API，不能
  靠重定向来迁移凭据请求；规范地址通过不带凭据的 discovery 获得。
- 能力警告通过事件/短暂提示显示；畸形工具 JSON 的诊断不再拼接原始参数或
  解析器的数据摘录。日志与 transport snapshot 不携带音视频 base64 正文。

验证证据：`remote-login-security.test.mjs` 使用真实 HTTP 重定向服务器和
独立 trap，307/308 下 trap 接收次数为零；覆盖 CLI helper、刷新、解绑、SDK
刷新与 RPC。Web 浏览器契约测试注入 `javascript:` 登录链接，实际打开及
呈现的仍是本地固定登录路径。Android `GatewayUrlTest` 与
`DeviceApiStreamTest` 覆盖恶意登录码和带凭据事件流的重定向拒绝。

## 历史静态告警的逐类处置

复核时主分支有 25 个 open 告警；以下不是按严重级别一键忽略，而是核对
每个实际来源、权限边界和数据去向。修复后的编号可能因扫描重新归并而变化。

| 告警／位置 | 复核结论与防护证据 |
| --- | --- |
| #42、#44–48：CLI 远程网关请求 | 网关由 OS 用户选择或由该已选择网关的 discovery 指定；不是公网网关接收任意 URL 后替访客请求。HTTPS/无 userinfo 校验允许企业私网；不能把私网地址一律封禁。本轮再加凭据请求禁止重定向与传输陷阱测试。 |
| #43：模型目录请求 | Base URL 来自所有者配置，项目级路由需事先信任；目录缓存命中前也重新检查信任。分页与重定向必须同 origin，跨 origin 的 trap 不会被访问。见 `provider-security` 与 `model-catalog` 测试。 |
| #30–35、#39–41：会话、重放、原子写入路径 | session ID 先通过严格 ASCII 文件名段校验，再拼接固定私密目录；实际认证 HTTP 测试覆盖双重编码、UNC、驱动器、控制字符和污染索引。原子写替换叶子而非修改外部硬链接 inode；重放另有 no-follow/身份钉住检查。见 `codeql-session-path-guards`。 |
| #37、#53：文件夹大小写别名／realpath | 用户路径先过词法根边界，再过规范化边界和私密目录保护；大小写别名要求根目录物理身份一致。不是只做字符串大小写比较。见 `device-folders-browsing` 的越界、别名及凭据路径测试。 |
| #20–21：API Key SHA-256 | 摘要用于模型目录缓存隔离，不是密码验证或用户登录存储。缓存不保存原始密钥，换密钥不会复用旧目录。不能把密码 KDF 误用来修复一个不存在的密码验证器。 |
| #19：文件提及转义 | 输出给自定义 `@` token 解析器，不交给 shell 或 HTML；反斜杠、空格、引号和 shell 元字符有往返测试。这个函数不能复用为 shell quoting。 |

早期漏洞和修复过程保留在 [preview.0 复核](security-review-1.0.1-preview.0.md)。
没有为清空数字禁用 CodeQL 规则、排除生产目录或批量 dismiss 告警。
上述受项目自定义防护限制的路径/缓存告警可能继续显示 open；这不应被写成
“扫描零告警”，也不能仅凭 scanner 标签就认定已绕过实际鉴权。

`6ca13f1` 的 [后续扫描](https://github.com/kkelly-offical/kkcode/actions/runs/35727419569)
已不再报告 Web 登录导航 #49–52。该验收分支仍有 17 个 open 静态告警：
上表的 14 个路径／缓存／提及语法项、模型目录 #43，以及集中校验后的
网关请求 #54、WSS #55（原 #42、#44–48 归并后的同类数据流）。后两项的
网络目的地仍由用户所选网关决定，不是从远端 RPC 接收的任意目标；同样
适用上表边界和真实 redirect-trap 测试。这里明确保留数量，不宣称零告警。

## 支持边界

选择恶意网关相当于把该网关作为受信任组织设施；它本来就能查看转发内容。
拥有同一 OS 账号并能修改私密状态、程序或环境变量的攻击者不在远程 RPC
隔离保证之内。生产还需账户隔离、TLS、限制管理入口、密钥托管和恢复演练。
本轮 npm 审计结果不代表容器基础镜像、企业 SSO 租户或 Android 商店认证。
最终扫描链接与发布证据见 [本轮台账](preview.2-worklog.md)。
