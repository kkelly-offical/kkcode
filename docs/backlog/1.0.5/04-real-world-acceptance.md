## VAL-01 · P1 · 完整模型质量与真实 Ultra 交付闭环

- 类型／状态：成熟度验收缺口／待补验。
- 现状：旧 v3 是 108 通过／11 失败／1 错误，关键恢复未全过；v4 六次专项为
  4 通过／2 错误。当前真实任务评测不能冒充已测完整 Ultra 自修复交付或同模型 A/B。
- 范围：先处理 [REC-01/02](01-recovery-and-model-behavior.md)，再冻结完整评测定义；
  如改公共 grader 必须使用显式新版本。另取公开专用多模块仓库验证严格 Ultra。
- 验收标准：
  - [ ] 固定候选、模型路由、任务定义、依赖、限额，完整 60×2 分母不删除失败或缺测。
  - [ ] 达到批准计划的成功率目标且关键安全／恢复全过；不拼接不同定义或候选成绩。
  - [ ] 真正完成“实现 → 独立验收失败 → 有界修复 → 复验 → 候选绑定交付”流程。
  - [ ] 保护宿主判据、原件和独立测试；无法完成时正确报告，而非修改判据伪造成功。
  - [ ] 交付为可审查 GitHub PR／GitLab MR，不自动合并、发布或覆盖用户未提交工作。
  - [ ] 同模型 Harness A/B 报告成功率、波动、成本、上下文、耗时和人工干预，不能仅有比较脚本。
- 建议后续实现提交：`test(acceptance): verify strict Ultra delivery on a real multi-module repository`。
- 依赖：**新的**有限推理授权和验收仓库授权。旧本机授权窗口已过期，预算不自动重置。

## VAL-02 · P1 · 严格执行跨平台及 Android 实体设备

- 类型／状态：实机覆盖缺口／待补验，必要的平台适配须独立立项。
- 已完成：Windows/macOS/Linux 核心 CI、六组 Chrome/Edge、Android 模拟器及
  公开 APK 的更新策略和签名检查。不能把这些重新写成“没有支持／没有测试”。
- 未完成：Windows/macOS Docker Desktop 下完整严格隔离链，以及实体手机 UI 体验。
  原生宿主某些依赖／LSP 安全路径明确仅支持 Linux；Docker 存在不等于这些原语已适配。
- 验收标准：
  - [ ] 对每个 CLI/SDK 路径标明实际运行宿主与后端；不支持项明确拒绝，不静默降级。
  - [ ] 真实验证路径映射、权限、私密文件遮蔽、限额、取消清理、依赖和 Office 作业。
  - [ ] 不关闭 OS 安全策略／浏览器沙箱，不使用个人 profile 冒充授权的临时 CI 环境。
  - [ ] 实体 Android 覆盖安装升级、浏览器登录回跳、SSH 后台与重连、设备切换、输入法及附件。
  - [ ] 记录设备／OS／镜像／版本和证据，模拟器、策略解析与实体手机 UI 分别报告。
- 建议后续实现提交：`test(platform): record real strict-runtime and physical Android acceptance`。
- 依赖：获准的设备、Docker 环境和测试账号；不得自动使用生产设备／凭据。
