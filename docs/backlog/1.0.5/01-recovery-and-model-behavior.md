## REC-02 · P1 · C11 所有权切换评测的顺序假设

- 类型／状态：已确认的**评测驱动缺陷**／待修复。
- 现状：通用驱动在首个任意工具后换 owner，却随后假定写入标记已存在。
  公开合成 `list → write` 对照正确阻止旧 owner 后续写入，但判据读取不存在文件而报
  `ENOENT`；write-first 对照通过。没有因此复现产品所有权隔离失效。
- 范围：独立定义故障切点和断言前置条件，用宿主事件／持久状态证明隔离，而不是
  默认“第一个工具一定是写入”。先审查通用机制，不读取封存题面、答案或模型实现调试。
- 验收标准：
  - [ ] 首工具为 list/read/write、工具失败、切换前后取消均有公开合成正负控。
  - [ ] 晚到旧 owner 结果不得提交；新 owner 不得盲目重放未知副作用。
  - [ ] 文件未产生与真实恢复失效分别报告；真正越权提交或重放必须被负控抓住。
  - [ ] 评分／驱动语义变化使用新的显式定义和指纹；不修改冻结 v1–v4 或旧成绩。
- 入口：`evaluation/v1/recovery-drivers.mjs`、`test/evaluation-recovery.test.mjs`。
- 建议后续实现提交：`fix(evaluation): remove first-tool write assumption from owner takeover`。
- 关闭证据：新定义版本、公开对照日志、独立复核及新运行结果的链接。
