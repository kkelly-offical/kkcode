## SEC-01 · P1 · 执行期间的硬磁盘／inode 配额

- 类型／状态：生产加固缺口／待设计、实现和实机验收。
- 现状：CPU、内存、PID、时间、输出和部分单文件／归档限额已经存在；
  宿主 bind 工作目录仍无执行期间的硬性总磁盘／inode 限额。执行后发现超量
  不等于执行中已阻止写满工作卷。
- 范围：先明确支持的后端和文件系统，提供宿主可证明生效的任务卷／配额方案，
  再暴露可检查的能力信息。不要把 tmpfs 或内存限制冒充整个工作区的磁盘保护。
- 验收标准：
  - [ ] 在专用限额测试卷中分别触发字节额度和文件数量额度，不填满宿主真实磁盘。
  - [ ] 构建、获批安装脚本、长任务和子任务均不能绕开合同给定的适用范围。
  - [ ] 达到限额时有明确错误和可恢复证据；未知写入不自动重放，不清除用户原件。
  - [ ] 取消、崩溃、恢复、并发任务和清理后的容量回收有真实测试。
  - [ ] 平台／权限／文件系统不支持时明确拒绝强隔离声明，不自动降级伪造通过。
- 建议后续实现提交：`feat(isolation): enforce task-volume byte and inode quotas`。
- 依赖：专用测试卷／隔离环境的权限；生产部署另行授权。上线前维持独立卷、容量监控
  等部署要求，不宣称已有跨平台硬配额。
