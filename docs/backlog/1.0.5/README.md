1. REC-02、REC-01 和 DOC-01：先让恢复证据与当前状态可信；REC-03 同步做公开场景诊断。
2. ENV-01、SEC-01：补大型仓库严格执行的关键基础；SEC-02 持续逐项跟踪。
3. VAL-01、VAL-02：固定候选做真实仓库闭环和平台验收，不因测试缺口放宽隔离。
4. ENV-02/03、REL-01/02 按独立小提交推进；VAL-03 等资源齐备后验收。
5. VAL-04 完成真实试用，逐条关闭发现的问题，再按原计划评估是否具备1.1.0条件。

## 每项怎样关闭

- 子文档已写明现状、范围、入口、验收标准、依赖和**建议的后续实现提交标题**；
  标题是规划，不是已经存在的修复 commit。
- 开始时补负责人和工作分支；一项一组可审查改动。发现范围不同的新问题另开 ID。
- 记录复现、修复提交、测试命令／结果、候选与环境指纹，以及剩余边界。
- 勾选完成必须附证据；“没有资源”“测试未触发”“skip”“模型说完成”都不是通过。
- 推理必须重新获得有限窗口和额度；旧本机授权已到期。不复用聊天旧凭据，不读封存
  答案调参，不改历史分数，不因免费模型而无限重试。
- 源码变更走 PR 和所需审查，不旁路 main 保护；不重新打已发布 tag，不覆盖 npm/APK。

## 暂缓与明确不自动扩展的范围

- **公共网关镜像发布：用户已决定暂不处理。** 继续从源码构建，不列为当前发行阻断。
- 生产网关／示范 VM 升级由部署者另行安排，需要独立授权；不在这些待办提交中执行。
- 严格 Browser 的 HMR/WebSocket、Bridge 嵌入 frame／全局按键、Office 宏／加密等
  保持当前明确边界。如需扩展，先确认需求和权限模型，不把安全拒绝自动当作 bug。
- 不新增 Web SSH 代理、跨设备浏览器调度、桌面远控或专用浏览器直播控制面板。
- 继续1.0.x／1.0.5 Preview迭代；1.1.0仍需成熟度验收与单独发版确认。
