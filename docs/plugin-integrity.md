# 托管插件来源、升级与再授权

1.0.5 Preview 为 `kkcode plugin install/update` 管理的插件建立私密来源锁和内容哈希。它不把可执行插件变成沙箱：批准 Hook、命令或其他可执行集成，就是信任该插件在宿主权限内运行。严格委托任务不加载这些宿主扩展。

## 安装与检查

支持固定 npm 精确版本、HTTPS Git 完整提交 SHA、明确的本地目录。拒绝浮动版本、含认证信息的 URL、符号链接/硬链接/特殊文件与未锁定 `.git` 内容。npm 安装不运行生命周期脚本，校验注册表完整性；Git 克隆/检出不读取全局 Git 配置或启用凭据助手、Hook 等仓库执行点。本地来源固定到规范绝对路径，今后不会因工作目录变化改换来源。

```sh
kkcode plugin install example /absolute/path/reviewed-plugin
kkcode plugin inspect example
kkcode plugin approve example --confirm-hash 检查输出中的完整SHA256
```

以 `kkcode plugin --help` 的当前参数形式为准。先检查源码、执行命令、网络端点、权限和来源，再确认哈希；复制批准命令不等于完成代码审查。

新可执行内容、Hook/MCP 等集成或提升的 Agent 权限不会自动启用。升级新增能力、改变来源/提交、改变可执行或集成内容，会进入待批准禁用状态。MCP 的独立 JSON 命令变化也会触发再授权。顶层和嵌套权限字段使用同一套优先级解析，不能通过别名冲突绕过审查。重复执行无变化的更新不能清掉待批准状态。

纯技能文本且能力不变的明确更新保留兼容行为；原本被禁用的插件不会因更新自动启用。保留原有手工可信兼容目录的信任语义；旧托管安装若没有私密锁，先禁用，等待明确审查，不能从旧安装标记自动取新来源。

## 更新与加载

```sh
kkcode plugin update example
# 明确改变来源时：
kkcode plugin update example --source npm:example-package@1.2.3
```

默认更新来源只取用户私密锁，不信任包内 `kkcode-install.json`。加载前校验来源标记、完整内容和状态。内容意外变化、锁损坏或缓存损坏时拒绝加载，不自动给新内容授权。

批准内容复制到 `plugin-content/<sha256>`，新版本用新地址。管理器不覆盖旧地址，避免已加载模块的相对导入在升级中突然指向另一套代码。更新后重新加载扩展/启动新会话，使新实例采用新版本；已运行 Hook 不宣称可即时撤回。内容寻址不是对恶意本机用户的文件系统防护：同一账号拥有写权限时仍需系统安全与私密目录保护。

删除操作移动到 `plugin-trash`，可人工恢复。旧内容缓存暂不自动回收，避免删除活跃导入或审查证据；容量检查时请把它计入用户状态目录。没有经过审查的包不要仅为了消除报错重新批准。
