# 严格任务持久费用预算

本机制覆盖通过 `createRunCoordinator` 启动的严格父任务和任务图子任务。普通交互会话原有的用量提示／预算设置仍然兼容，但不能混称为这里的持久逐请求保证。

## 新任务必须明确额度与期限

CLI 的任务 JSON 除 `contract`、`acceptance` 外，必须包含：

```json
{"limits":{"budgetUsd":5,"deadlineAt":1800000000000}}
```

示例时间必须替换为实际未来的绝对毫秒期限，最长七天；不要复制成永不过期配置。SDK 对应：

```js
const run = await coordinator.start({
  contract,
  limits: { budgetUsd: 5, deadlineAt: Date.now() + 60 * 60 * 1000 }
})
const result = await coordinator.execute({ runId: run.id, prompt: contract.objective })
```

SDK 未给额度时保存零预算，不发送推理；CLI 可以用零预算和 `--prepare-only` 准备任务。后续恢复不能增加额度、延长期限或重新计算一份“全新剩余预算”。旧的无预算任务也不会悄悄获得付费授权。

### 显式本机免费评测

本机已部署模型可以使用单独的宿主 `local-free` 能力，不必填一个虚构的正美元预算。它要求真实宿主回调确认、四项完整零单价和真实监听进程核验，绑定字面 `127.0.0.1`／`[::1]` 的精确端点、协议、模型、凭据 HMAC、PID、启动时间和监听 socket。当前进程核验要求 Linux；没有该原语的系统不退回“只看 URL 就信任”。DNS 名称、远端地址、查询凭据、端口／模型／凭据切换、JSON 伪造授权或更换监听进程均不能复用授权。

持久账本仍保存 `budgetUsd: 0`、实际 `spentUsd: 0`，另存有限的 `maxRequests`、累计 `maxTokens` 和原有绝对期限。每次请求先持久化 `inputBound + maxOutputTokens` 的 `tokenAllowance`，已使用授权不退款；`reservedTokens` 表示累计保守授权量，不是供应商实测用量。一次只能有一个在途请求，重启不重置额度；未知结果即使金额为零也会停止继续请求。免费模式不授权任务图转授，不准追加新价格／路由档案。

只有这个当前仍有效的真实宿主能力允许向该精确 loopback 服务发送 HTTP 认证头，且每次请求重核监听进程、禁止重定向。普通 HTTP 凭据保护、普通零预算不推理、出域策略和工作区信任不变。“免费”指操作者明确确认没有外部 API 账单，不意味着 GPU、电力或服务器资源没有成本，也不是对任意本机代理的自动信任。真实模型评测仍须独立授权有限请求／Token 和期限，与无模型参考自检分开记分。

`taskGraph` 是父任务内的委派上限，不能大于父 `limits`。开始一个子任务前，先在父账本预留该子任务的全部额度；子任务各请求在自己的账本扣款，结束后父账本按子任务实际金额结算。这样父自己的模型请求加上所有子任务不会各自绕开总额限制。

## 请求前预留、完整回执后结算

每个实际推理请求都有唯一请求 ID。在 HTTP 发出前，宿主先向 SQLite 提交预算预留并等待确认；同一个 ID 不能再次当成新授权。

预留使用已批准的核价／上下文窗口 `context_limit`、输出上限 `max_tokens`，以及对应模型完整的 USD 输入／输出／缓存读取／缓存创建单价。完整输入计数或保守边界超过这份冻结窗口时，即使余额很多，也会在预留和推理前拒绝；不会沿用旧单价自动跨越长上下文费率分段。模型开始前，宿主把价格和窗口快照加入真实合同确认，并保存到仓库外的 SQLite 预算档案；后续请求只使用这份不可变快照，不重新读取模型可编辑的 `usage.pricing_file`。明确的私有模型价格可以放在用户配置指向的 `usage.pricing_file`：

```json
{
  "currency":"USD",
  "per_tokens":1000000,
  "models":{"my-private-model":{"input":1,"output":2,"cache_read":1,"cache_write":1}}
}
```

价格和窗口缺失、模型 ID 只有前缀匹配、缓存单价靠回退猜测、目录价格过期、临时切换地址／凭据后仍只有旧目录价格，均不能作为严格放款依据。普通会话的前缀估价兼容保留，但不是严格预算证据。剩余额度不足以覆盖已批准档案的保守预留时，停止请求并由宿主重新规划任务；不会静默选择更便宜的模型。单纯缩小客户端 `context_limit` 并不证明上游真实分词数或计费上限变小，不应把它当作降低供应商实际收费的保证。

档案绑定完整端点、协议、渠道、模型和凭据作用域，只存 HMAC 指纹，不保存 API Key 或带查询参数的地址。更换模型／端点／凭据作用域，需要新的真实宿主价格档案确认；同一个作用域不能通过追加另一份更低价格替换现有档案。确需调整同一路由费率时，新建明确批准的任务。降低本地价格文件、重启内核、把文件复制到子任务或更换角色，都不会降低已批准的费率；子任务继承父任务已批准档案。界面远程预算摘要不暴露这些私密档案。

收到完整的上游用量后才按实际渠道／模型结算。Chat、Responses、Anthropic 和 Ollama 的适配器保留进程内来源证明；只有上游实际返回必需计数才有效，缺字段补零不是计费证据。流式累计帧不重复收费。严格预算作用域内关闭传输层自动重试和异步模型标题，防止未知收费被放大；普通会话仍保留既有重试行为。

严格结算同时核对上游真实 `model` 和处理档位。缺少模型身份、请求别名返回不同 dated snapshot、出现 priority 等未核价档位，都会保存未知费用并停止，不把请求模型名填回去伪造上游身份。请配置服务端实际返回的固定版本 ID 并明确登记该 ID 的价格，再启动新任务；这里没有自动确认别名映射。现有请求体白名单不透传 `extra_body`，不开放服务端托管工具、后台任务或优先处理等额外费用选项。

## 完整输入的预检与媒体边界

计数与发送共用宿主复制的一份不可变内容快照，包含系统提示、工具 schema、历史消息、工具结果和原生续接。调用者在计数等待期间改写原数组，不会改变随后发出的内容。

- 文本输入按完整 JSON 的 raw／NFKC／NFKD 三种 UTF-8 字节数取最大值，乘以二覆盖结构化参数二次编码，再加固定和逐消息／工具模板余量。它针对常见字节／字符和 Unicode 规范化分词器，不是 `字符数÷4`。超过 16 MiB 或结构过大直接拒绝。
- Responses 优先调用官方 `POST /responses/input_tokens`；同一地址、凭据、协议、模型和输入投影，去掉生成侧字段，返回必须是 `response.input_tokens`。完整精确计数优先于文本字节边界，避免其过度保守误拒；官方接口覆盖图像、文件、工具结构和消息格式的处理后输入计数。见 [OpenAI token counting](https://developers.openai.com/api/docs/guides/token-counting)。
- Anthropic 的 `count_tokens` 官方定位是估计而非精确值；当前为其多模态输入预留两倍计数加 4096 余量，不能宣称数学上的绝对上界。见 [Anthropic token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting)。
- Chat／Ollama 没有这里可依赖的通用远程多模态计数；严格任务遇媒体时明确停止。Responses 兼容端点若不支持 count-only 接口，文本可以回到完整字节预留，图片／不透明续接不会盲猜。普通交互会话行为不变。
- 原生 Ollama 的预算档案与推理共用渠道、专用端点和模型前缀解析，不依赖 OpenAI／Anthropic 模型目录。最大输出通过 `options.num_predict` 发送；缺少原始 `prompt_eval_count`／`eval_count` 仍是未知结果，不补零伪造计费证据。参见 [Ollama 参数说明](https://docs.ollama.com/modelfile#valid-parameters-and-values)。
- 可变的远程 URL 附件不能借一次计数授权另一次抓取；严格任务要求固定的内联附件。Browser 截图产生的固定 PNG 可走 Responses 计数，不需要把截图上传到外部 URL。

计数连接同样执行出域策略、工作区信任、凭据传输保护、禁止跳转、超时和取消，审计仅记录元数据。这里没有用真实付费账号宣称兼容网关已验收，也不把供应商返回计数的可信性变成对任意自定义 tokenizer／隐藏提示词的保证。

Chat 的字节边界可能保守误拒；不要通过忽略检查继续执行。可精简工具定义／历史、换用实际支持精确计数的 Responses 渠道，或新建经宿主明确批准更大窗口及该范围适用最高单价的任务。窗口、输出和价目都不会由模型自行修改。区域、长上下文等供应商差异仍需部署方在批准费率时核对；本地账本不是供应商银行账单。

## 崩溃、取消与未知费用

- 已知尚未发出 HTTP 的取消，可以可靠结算为零。
- 请求已经发出但超时、响应缺字段、消费者提前关闭、结算持久化失败，保留预留并标记未知，禁止再发新的付费请求。
- 进程被强制结束时，预留已经在 SQLite。新宿主接管把悬空预留转为未知，不能靠重启重置额度。
- 实际上游费用超出预留时，保存更高的风险敞口并停止；不把它强行截成预算数字。

`RunRecord.budget`／`store.getRunBudget({runId})` 返回总额、已结算、在途预留、未知金额、绝对期限和请求记录。Web／Android 可以展示最小汇总，不需要暴露请求中的模型或其他私密信息。

未知金额需要宿主通过 `reconcileModelBudget` 提交实际核查金额、证据引用和真实批准。模型回复、缺少报错、重新运行一次或手工删账本都不是核查。只有计费核查完成也不代表工具副作用已经核查；两条门禁独立存在。

预算使用部署方提供／确认的价目、窗口假设和上游计数，不是银行扣款锁，也不能约束外部供应商违反其计费协议。当前本地上下文估算不是任意私有模型分词器的形式化上界证明；在尚无可信精确计数的端点，不能宣传“任何情况下都绝不超过供应商收费上限”。未知费用保持可见、停止继续扩大风险；不会声称掌握没有收到的供应商账单。

## 验收

`test/request-budget.test.mjs` 使用真实本地 HTTP 验证零请求拒绝、并发预留、完整／部分用量、真实模型／档位、禁止自动重试和取消窗口。`test/strict-input-budget.test.mjs` 覆盖大输入／Unicode 展开、可变对象快照、两轮图片＋原生续接的真实 count/inference 请求一致性，以及计数不兼容、超时、取消、跳转和出域拒绝。`test/request-budget-crash.test.mjs` 启动真实内核子进程，在 HTTP 已发出而未回包时强制终止，重新接管后确认持久未知预留仍在且请求次数仍为一次。`test/strict-pricing-snapshot.test.mjs` 让真实 Docker 工具把项目价目改为零，验证后续请求、重建内核及子任务仍按原批准档案受预算阻止。`test/task-graph.test.mjs` 额外验证父自己的费用与子任务结算之和，并结合真实 Docker 执行隔离子任务。这些均为受控 fixture，不消费生产账户额度。
