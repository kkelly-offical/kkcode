# 上下文、提示词与 Harness

[文档导航](README.md) · 当前源码：1.0.6（正式版候选）；[发行状态](versions.md)

## 上下文数字的含义

当前请求预算 = 系统提示 + 工具 schema + 转换后的历史/媒体 + 输出预留。
原先只估算历史会低估大工具列表、项目规则和插件注入；现在这些都参与压缩判断。
窗口优先使用明确配置的 model_context / provider.context_limit，否则使用内置回退。
本地模型若目录没有准确窗口大小，应显式配置，不应把模型名字猜测当成权威上限。

空对话且尚无有效用量时不显示上下文条。工具结果使用完整内容估算，缓存只保存
内容指纹做一致性检查，不用截短的预览代替计数。Responses 的加密续接不按密文字节数
计算，使用可用的推理 token 用量；未调用独立计数 API 时仍明确标作估算。

Web/Android 显示当前上下文而非累计用量：

- `estimated`：本地启发式估算，图片等采用保守开销，不等同于计费。
- `count-api`：支持时使用模型服务端计数，系统与工具不再重复累加。
- `provider-usage`：最近响应输入及输出形成的已占用上下文。
- `strict-upper-bound`（1.0.5）：严格任务完整请求的保守输入上界，用于发送门禁与
  提前压缩，不是模型实际token或计费用量。Web/Android标“保守上界”，CLI标`BOUND`。

组成项始终是用于诊断的估算，因此服务端总数可能不等于组成项之和。
下一轮加入新工具输出等后会重新计量。输出预留默认最多 16,384 tokens，
小窗口默认最多窗口四分之一；显式 max_tokens / max_output_tokens 会参与限制。
压缩不能解决超大的固定系统提示或工具声明；仍超窗口时明确报错，不丢弃用户内容
冒充发送成功。原有 CLI/headless `turn.usage.update` 结构不变，新数据在
`session.context.updated` 与 `sessions.get.context`。

严格任务的普通估算可能明显低于保守上界；例如界面曾估计21%，并不能证明下一次
完整请求一定能装入窗口。1.0.5在自动压缩与发送门禁中使用同一输入上界，并在压后
重新核验；服务端实际usage仍单独显示。组成项是诊断估算，不要求相加等于上界。
窗口配置不随失败自动扩大，也不会绕过用户选择的模型网关。

严格发送门禁同时检查“完整输入上界＋最大输出预留”，包括不经过聊天循环的摘要
和直接SDK调用。取消信号会进入摘要请求，并在历史原子替换的提交点再次检查；
取消不是已发送请求的费用退款，也不抹除未知结果。严格摘要除原有估算缩减外，还需
在同一继续对话渠道、系统提示和工具声明下证明严格上界正向缩减，否则保留历史。
显式SDK压缩若未提供未来系统提示/工具，只能证明历史部分缩减，下一完整请求仍须
重新过发送门禁。Unicode兼容字符展开不能让“大摘要”伪装成有效压缩。

## 附件按需召回（1.0.6 Preview.1）

客户端压缩会将已上传的文本、图片、音频和视频内容保存为当前会话的私有归档，
然后在摘要区和保留的最近轮次中都换成简短描述及引用；原文不再进入摘要请求或
“原始用户要求”投影。附件较多时只显示有界索引，完整目录也按需读取。
文本用`artifact_read`分页读取或`artifact_search`定位，图片、音频和视频可用
`artifact_read encoding=media`单独召回（最大20 MiB，仍须渠道支持该媒体类型）。
召回的内容是待分析资料，不会成为新的指令或权限。文本召回只返回有界页面或匹配，
按普通工具结果保留近期片段；再次压缩会移出召回的媒体，不自动重新注入整份上传文件。

归档受原账号、项目、会话或严格任务范围约束。换账号、范围变更、归档缺失或损坏
时明确失败，不重新下载旧URL、不执行原文件，也不扩大子任务权限。归档失败会
保留原始历史并拒绝本次压缩；取消、并发历史修改和压缩后无有效缩减的保护仍然生效。
已混入普通文字的粘贴内容不能可靠区分为附件，仍按用户原始输入保留与投影。
启用服务端原生压缩的渠道在历史含附件时，达到客户端阈值仍先执行上述归档路径。

## Anthropic 原生压缩

原生压缩默认关闭；模型名称包含 Claude / Opus / Sonnet 不证明渠道支持 beta。
确认所使用的认证 Anthropic 渠道支持 `compact-2026-01-12` 后，可显式配置：

```toml
[provider.my-anthropic]
type = "anthropic"
native_compaction = true
compaction_trigger = 150000
```

`compaction_trigger` 最少 50,000 input tokens；基础连接、密钥和准确窗口大小仍需单独配置。
原生摘要只有在完整响应结束后才作为私密续接状态持久化，绑定渠道地址、模型、凭据、
生成它的历史和对应回答。模型切换、历史改写、状态损坏、未经认证的原生块都不能触发
历史裁剪。Web/Android 投影不包含该私密状态。旧消息保留在本地，后续请求仅在验证通过
时采用原生摘要；明确的“不支持原生压缩”请求错误可在任何输出产生之前回退普通请求。
如果请求已经依赖原生摘要缩短历史，则先返回内核做客户端压缩和预算复检，不能在旧预算下
突然展开并重发全部原文。
已经有输出或工具调用的流式失败不会因此重新执行。
计费用量包含服务端压缩迭代；当前上下文占用只采用最后一次正常生成迭代，
不把整个压缩过程的累计消耗误显示成当前窗口大小。

原生能力不会关闭完整请求硬预算检查；无法可靠计数或仍然超限时，先尝试客户端压缩，
仍然超限则停止。客户端摘要提交使用生成前的完整历史与会话模型快照做原子比较，
遇到并发输入、撤回、模型切换或另一轮压缩时拒绝过期提交，不删除新内容。
当前回合会明确停止，避免用已经过期的模型或已撤回的任务继续执行。
保留最近消息时会向前扩展边界，不能拆散工具调用与结果；配对缺失或没有安全前缀时
保留旧历史并说明原因。非空摘要仍需让包含包装/产物索引的完整候选估算tokens严格减少；
没有缩减就不提交。该判据不是摘要无损保证，能否适配上下文窗口仍由完整请求预算检查。
实际 Anthropic 账户长会话验收仍需用户授权的模型额度；当前回归使用受控 HTTP fixture。

## 提示内容与诊断

提示缓存归属单个内核，内容指纹覆盖 Agent 正文、Skill 描述、工具描述/schema、
模式/权限、项目上下文、用户规则及记忆。外部内容标记为参考来源，不成为更高优先级
系统指令。模型配置名不是知识截止时间证明；不要在模板里虚构训练日期。

```sh
kkcode prompt list
kkcode prompt show --type tool --name browser.txt
kkcode prompt inspect --session SESSION_ID
```

`inspect` 输出最后一次真实请求组装的块标签、来源、指纹、估算、广告工具名和预算；
不输出提示正文、工具参数或凭据。没有运行过新版本回合的旧会话会说明尚无记录。
诊断固定模板的位置不依赖当前工作目录。模板来源与运行时能力应保持一致，不能仅
靠抄一份更长的系统提示替代权限、恢复与协议实现。

大工具文本在显示截断前进入本机会话产物库，模型通过受权限管理的
`artifact_read` / `artifact_search` 按需读取，不必为了找回日志重跑命令。
压缩会保留宿主写入的产物引用；部分捕获、容量不足和归档失败均明确标记。
具体字节边界、身份范围和未接入功能见 [产物SDK与会话归档](sdk-storage.md)。
模型和内置网页请求还受 [数据出域策略](data-policy.md) 约束；这不代替Shell隔离。

## 按需工具与组合

`tool_search` 同时查找 MCP 和可选内置工具，并返回完整参数及详细手册。
基础上下文保留紧凑说明；可选 Browser、Web、Git、文件操作等按需激活。
`tool.discovery.enabled: false` 恢复完整声明面；执行期白名单、Skill 限制和审批不变。

`tool_batch` 接收 `calls: [{name,args}, ...]`，1–8 项串行执行：

- 子项逐一走原工具执行路径，并产生独立审计、工具日志和审批。
- 失败/拒绝/取消后不继续后续子项。
- 不允许嵌套 batch、委派、模式切换或 Skill 激活；无任意 JS/循环。
- 非事务，前面成功的更改不会自动回滚。后续参数依赖前面结果时请分开调用。

## 中断恢复与无进展

有副作用的工具执行前，在设备私密 `operations/SESSION_ID.json` 持久化操作元数据。
日志不保存原始参数/凭据；每会话保留最多 256 条已解决记录和 32 条未解决记录，
未解决记录不会被容量轮转悄悄删除。

执行过程中崩溃或异常无法证明结果时，同样参数的新尝试被拦截为
`tool_outcome_unknown`。先用只读工具或人工检查实际文件/远端状态，再由设备所有者：

```sh
kkcode session operations --id SESSION_ID
kkcode session operations --id SESSION_ID --resolve OPERATION_ID --confirm-inspected
```

确认只表示已经检查，既不验证结果，也不撤销或重新执行。仍在执行的操作不能确认。
这减少重复副作用，不宣称跨外部系统 exactly-once。客户端 RPC 的请求 ID 去重是
另一层保护，不能与工具结果恢复混为一谈。

普通回合检测 1–3 项的重复工具序列：同参数、同状态、同结果重复 3 次提醒换方法，
6 次暂停并保留已有工作。输出在变化的正常轮询不触发。Ultra 仍保留自己的阶段、
预算和目标门禁；停滞不是完成。

自动收尾只核对任务状态，不再隐式 `npx` / build / test / lint。需要执行的检查
必须通过常规工具及审批，最终报告要区分已验证、失败和未验证。

## 本轮源码：证据保留与完成检查

真实工具结果与系统控制消息分开处理；压缩不因旧记录带有`synthetic`标记就丢弃真实结果。
失败与近期回执进入有界证据摘要，用户原始要求保留在同会话、不可变的私密产物中。
活动上下文只携带有界的约束投影；需要精确核对时使用`artifact_read`／`artifact_search`
读取原文。摘要不是新的任务、权限或“已经读过文件”的证明。
严格SDK压缩若只有请求预算、没有对应任务的产物访问能力，会保留完整原始要求；
若因此无法减少上下文或适配窗口则保留原历史并拒绝压缩，不创建随后无法读取的
普通会话产物来冒充任务产物。自动运行时压缩沿用实际任务的产物访问能力。

文件已读状态按内核、会话与工作区隔离。别的会话读取过、摘要说读过、或重启前读过，
都不能替代当前会话的真实读取；编辑仍受原读取／变更检查约束。

公共完成检查只观察已有记录，不自动执行命令。代码修改后需要更晚的、可识别的真实
检查回执及结构化成功退出码；失败按命令、参数、工作目录和环境保留，不能被无关绿灯
冲掉。Shell掩盖失败或无法识别的命令不能成为验收证据；文档专属变更可使用适当的
`git diff --check`，不把它当作代码测试。未完成/受阻ToDo、未收束子代理和未知副作用
不能被最终回复“已完成”覆盖。取消的ToDo不自动当作待执行任务重放。

后台启动成功只表示已提交。完成检查会读取本会话的规范任务记录，等待真实进程收尾；
检查必须在后台修改结束之后启动，不能拿“后台还在写文件时已经跑完”的测试充数。
`tool_batch`、`tool_program`等组合工具的内部调用同样进入证据记录，而不是只看外层成功。
关闭可选`agent.verify_completion`不会关闭后台运行中、未知结果和子代理未收束的生命周期门禁。

新回合从宿主记录的回合终态恢复未收束证据；摘要、模型正文和任意JSON标志不能清除它。
历史上缺少规范终态的旧记录不会被追认已验收。未知操作需人工核查后明确确认，确认本身
也不能替代新的测试。验证环境值不复制到精简记录；仅保留受控身份摘要，未知环境覆盖、
缺少真实启动时间或shell通配展开的命令不作为可靠验证证据。

`checks_observed`表示观察到检查进程回执，不是完整语义验收，也不替代Ultra或严格任务的
独立验收。工程回归与真实模型质量分开记录，见[本轮实施记录](implementation-1.0.6-preview.0.md)。

### 可操作的检查与恢复

当前候选在新前台检查失败或结果未被独立核实时，于下一步模型行动前提供私有定位提示，
不必等到最终报告被拒绝才发现问题。单项检查独立补跑；失败的`&&`组合按相同顺序整体
补跑，并保留参数、目录和环境。提示按检查身份去重，每回合最多8条；最终验收始终独立
执行。真实工具输出不被追加或改写，内部提示不显示为Web/Android中的用户消息。
未知效果、未核查历史、尚在运行的后台任务不会因此获得自动重跑许可。

输出过长时使用返回归档的`artifact_read`／`artifact_search`，避免在测试后串接`tail`
或`grep`而丢失实际测试退出状态。关闭可选完成验收时，不向系统提示注入整套完成验收
指南；基本验证习惯、权限、未知效果与后台生命周期规则仍保留。

交付质量还包括报告本身：文档修订需要验证接受与拒绝后的内容，修改日志需与原始输入、
最终文件和实际执行记录对应。自写断言通过不能证明章节、数字、修改说明或视觉效果全都
正确；最终报告应说明已验证的范围和剩余限制。

1.0.6-preview.1已补齐完成反馈与恢复链并随Preview发行。优先直接运行项目测试；
自定义文件、文档或API检查应编写真正失败会退出非零的断言测试，然后用
`node --test verify.test.mjs`或`python3 -m unittest`执行。只读/Plan任务不得为此改文件。
单纯输出PASS、任意shell的退出0、语法/空白检查都不证明功能正确。

通过Bash工具的`cwd`参数指定工作目录更清晰，例如：

```json
{"command":"npm test","cwd":"web"}
```

`cd web && npm test`也有确定的目录绑定。失败或掩盖结果的检查按参数、目录、环境
保留；在另一个目录跑同名命令不能清除它。动态/条件目录不能被假设为确定范围。
阻断反馈提供检查标签与原始记录定位，而不泄露环境变量值或自动执行检查。

编辑证据按规范化目标路径去重，多文件失败可逐文件修复；未修复路径仍阻断。
真正发生在宿主派发之前的参数拒绝有宿主未执行回执，不误计为已经发生的编辑；
模型、工具输出或metadata中的“没执行”声明不能代替该回执。

临时测试服务最好由一个有限断言程序管理：启动、等待就绪、断言、finally清理，
等待全部子进程退出后返回真实测试结果。单独启动的后台进程有独立操作账本；取消、
超时或未知效果仍不能自动算成功。`inspection-required`表示必须由会话所有者核查
真实文件、数据与进程，再在设备CLI使用前文的`session operations`确认对应操作ID。
确认不是回滚、不改写原取消/失败结果，之后还需真实检查；智能体不得代替用户确认。
Web/Android获得同一阻断说明，但目前没有独立的操作账本确认按钮。旧缺失回执不补造成功。

新的候选增量在执行前检查明确的POSIX后台列表：`server &`且后面没有显式`wait`时，
返回`bash_background_requires_owner`，整条命令未执行，不会先启动服务或创建重定向文件。
只给同一命令加`run_in_background: true`不能解决内部的未托管`&`；应移除`&`，让管理器
持有该有限命令，或编写会关闭并等待全部服务的测试程序。`... & wait`等显式收尾路径
继续可用；是否真的收尾仍以实际进程结果为准。Windows CMD的单`&`是顺序执行，不适用
此POSIX诊断。复杂脚本、命令替换和here-doc不会被这个词法检查当成已证明安全，仍由
原进程生命周期、隔离和未知效果规则处理。

宿主证明未派发的请求，不会被算成“已执行但失败的检查”；普通工具metadata中自行声称
`started=false`不能获得该证明。修改后的实际检查和既有未知效果仍需各自核实。

这种人工核查屏障会明确结束当前回合，而不是反复请求模型。提供者出错时也保留已知
验证结果，CLI/SDK可从`completion.verification`查看恢复依据；不把新一次报错说成验收通过。

详细改动与真实模型重测状态见[本轮实施记录](implementation-1.0.6.md)。

## 浏览器开发诊断

```json
{"action":"open","url":"http://127.0.0.1:5173","development":true,"websocketProtocol":"vite-hmr"}
```

`development` 是显式选择，默认 false；WebSocket 只允许当前明确打开的同源页面，
仍校验 DNS 固定地址、禁元数据/链路本地地址、字节和连接数上限。不自动跟随跨域
WebSocket 或升级为私人浏览器权限。非 Vite 服务可省略 websocketProtocol。
