## 本轮重点

- Agent、Auto、YOLO共用编码、验证和委派能力，区别在审批策略；Plan保留只读探索与规划，
  Ultra在公共内核上增加阶段编排。YOLO不绕过目录范围、组织规则、未知副作用或验收门禁。
- 子代理持久化父子归属、角色、权限、期限和运行租约，支持查看、消息、等待、续接和中断；
  失败、取消、未知和未完成状态不会因为有回复文本而变成成功。
- 会话ToDo跨回合保存，CLI、Web和Android均可折叠查看任务进度、负责人、依赖及子代理状态。
  多个任务可并行，空状态不显示；切换会话／设备和重连拒绝迟到旧数据，原按键布局不变。
- Bash使用结构化退出／超时／取消记录，取消传到受管理进程；后台检查点按运行尝试加锁，
  旧心跳不能撤销取消。启动后台任务只是提交回执，不是工作已完成。
- 完成检查观察真实修改和后续验证，包括组合工具的内部调用；后台仍写文件时的旧测试
  不算最终验收。停止保留已有改动和证据，不回滚，也不自动重放未知操作。
- 压缩保留工具结果、失败证据和原始要求；读取记录按会话隔离。严格任务只展示实际可用
  工具，避免无权限工具定义浪费上下文；原上下文预算、宿主授权和独立验收保持不变。

## 升级与客户端显示

公开核验完成后，CLI可明确选择预览渠道：

```sh
npm install -g @kkelly-offical/kkcode@1.0.6-preview.0
```

Android在更新设置选择Preview，下载后仍需系统确认安装。Web资源随对应源码／网关构建；
设备CLI、App、网关分别升级，不会自动替换其他端。子代理状态目前是远程只读展示，
没有添加未实现的启动／续接／中断按钮。待办“已完成”不是测试验证百分比。

公共网关镜像发行继续暂缓，可从本版本tag构建自己的镜像。本轮不升级企业生产网关、
演示设备或既有评测VM，不改变SSO、签名身份或信任范围。

## 证据与限制

本轮实现及本机回归见[实施记录](implementation-1.0.6-preview.0.md)。发行候选仍需
通过实际跨平台CI、CodeQL、包完整性、Android签名和安装检查；以对应SHA／产物核对，
不能用旧版本的绿灯替代。尚未运行或按环境跳过的测试单独列出。

普通委派的正数费用限制仍是运行费用估计，不是严格累计预算；硬预算使用宿主持久任务图。
普通聊天的审批不等于OS隔离，worktree续接仍需明确宿主交接；老Ultra阶段管理路径保持兼容。
单父会话超过1000条子记录会明确提示列表超限，而不是截断后宣布全部完成。

发布后的五类工程评测使用实际公开包、新的隔离工作区和独立计量：全栈、文档修订、
检索报告、艺术页面、多代理算法。它们与此前冻结的同模型对照队列分开，结果据实记录，
失败不隐去；少量场景不代表已经获得普适可靠性或达到1.1.0成熟度门禁。
